Яку проблему вирішено

Інтернет-магазин меблів мав розрізнені сирі дані — сесії, замовлення, товари, облікові записи, витрати на рекламу — без єдиної картини того, що насправді рухає бізнес.

Мета проєкту: об'єднати ці джерела в одну аналітичну модель і дати конкретні відповіді на бізнес-питання:


Звідки насправді приходять гроші (канали, пристрої, географія)?
Чи можна довіряти вбудованій прогнозній моделі виручки?
Чи приховують дані системні проблеми, непомітні на поверхні?

Основні висновки

Фінансова динаміка та валідація прогнозу

Чистий прибуток: листопад — 7.7 млн, грудень — 9.7 млн (+26% MoM), січень — 7.3 млн. Грудневе зростання сформувалось у перші два тижні місяця (передноворічний попит), після чого тренд пішов на спад.

Прогнозна модель точно вгадує сезонні хвилі й напрямок руху продажів, але систематично завищує абсолютні цифри виручки. Висновок: придатна для планування маркетингових бюджетів, але не для закупівель товару на склад.

Географія та пристрої

Ринок Americas — беззаперечний лідер продажів. Кореляція між усіма трьома континентами висока (r = 0.66–0.69), що доводить єдину глобальну сезонність (наприклад, Black Friday), а не ізольованість ринків.

Desktop і Mobile мають сильну кореляцію (r = 0.81): маркетингові активності однаково стимулюють обидві платформи. Tablet — поза основним трендом (r ≈ 0.50), і продажі через нього радше випадкові.

Маркетингові канали

Organic Search — головний драйвер трафіку. Сильний зв'язок між Organic і Paid Search (r = 0.81) показує, що платна реклама підігріває впізнаваність бренду, яка конвертується в органічний пошук пізніше. Social Search (r ≈ 0.45) розвивається автономно від інших каналів.

Cross-sell потенціал

Найсильніший зв'язок — між категорією Sofas & armchairs і системами зберігання: Bookcases & shelving units (r = 0.66) і Cabinets & cupboards (r = 0.66). Це готова основа для товарних бандлів і скриптів крос-продажів для підвищення середнього чека.


Критичні системні проблеми, виявлені в даних

Вада трекінгу неавторизованих користувачів. У 92% сесій відсутній user_id — звичайна поведінка неавторизованих гостей. Але при розрахунку виручки на користувача весь цей масив (заповнений технічним маркером -1) виглядає як один-єдиний "користувач", що формує левову частку прибутку магазину. Це не VIP-клієнт і не аномалія — це системна вада: сайт не розрізняє анонімних покупців між собою. Без унікальних Client ID неможливо порахувати коректний retention чи LTV.

Невидимий технічний збій. Кореляція між трафіком і продажами загалом дуже сильна (r = 0.79, p < 0.05), але 4 конкретні дні з високою активністю (2800–4100 сесій) дали нульову виручку — явна ознака збою платіжної системи чи кошика, непомітна без окремого статистичного аналізу.


Рекомендації для бізнесу


Виправити логіку трекінгу. Впровадити унікальні Client ID (на основі cookies/сесій) для анонімних користувачів — без цього неможлива коректна когортна аналітика, LTV і Retention Rate.
Розслідувати технічний інцидент. Передати 4 виявлені дні з нульовими продажами IT-команді для аналізу логів платіжного шлюзу.
Впровадити cross-sell скрипти. Передати знайдені товарні зв'язки (дивани + системи зберігання) відділу продажів для формування пакетних пропозицій.
Коригувати використання прогнозної моделі. Застосовувати її для планування маркетингових бюджетів (точна сезонність), але не для закупівель на склад (завищує масштаб).
